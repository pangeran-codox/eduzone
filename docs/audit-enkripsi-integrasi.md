## 4. Pola Enkripsi — Model & Cast

Ada **3 pola enkripsi** yang hidup berdampingan di codebase. Ini disengaja karena konteks penggunaan berbeda, tapi berisiko inkonsistensi jika tidak dijaga.

### Peta pola per model

| Pola | Kelas | Penyimpanan DB | Model yang memakai |
|------|-------|----------------|--------------------|
| **JSON-bundle cast** | `EncryptedAttribute` | 1 kolom teks/jsonb: `{"cipher_text","iv","key_id"}` | `School` (`principal_nip`, `bank_account_number`, `bank_account_name`), `CounselingSession` (`topic`, `result`), `StudentSikap` (`catatan_sikap`, `catatan_wakel`), `StudentRecord` (`description`) |
| **Split-kolom cast** | `EncryptedField:{prefix}` | 3 kolom: `{prefix}_cipher`, `{prefix}_iv`, `{prefix}_key_id` | (siap dipakai, belum ada model aktif) |
| **JSON-bundle trait** | `EncryptsViaGrpcService` | Kolom `{field}_encrypted` (jsonb): `{"cipher_text","iv","key_id"}` | `StudentSensitiveData`, `TeacherSensitiveData`, `StaffSensitiveData` |

### Status tiap pola

| Status | Item | Catatan |
|--------|------|---------|
| ✅ | `EncryptedAttribute` — implementasi sudah benar | Pakai `EncryptionClientInterface`, signature decrypt 4 param, throw `SensitiveDataEncryptionException` saat gagal |
| ✅ | `EncryptedField` — implementasi benar | AAD = nama prefix kolom, return array 3 kolom saat set |
| ✅ | `EncryptsViaGrpcService` — implementasi benar | base64 encode/decode sebelum/sesudah gRPC, AAD = nama field logis |
| ⚠️ | **Inkonsistensi AAD antar pola** | `EncryptedAttribute` pakai nama attribute Eloquent (mis. `"principal_nip"`), `EncryptedField` pakai prefix (mis. `"nis"`), `EncryptsViaGrpcService` pakai nama field logis (mis. `"nip"`). Konsekuensi: data yang pernah berpindah pola **tidak akan bisa didekripsi** karena AAD divalidasi kriptografis oleh AES-GCM — bukan cek kode. |
| ⚠️ | 3 pola berdampingan adalah risiko jangka panjang | Standardisasi ke satu pola untuk model baru direkomendasikan. Kandidat terbaik: `EncryptsViaGrpcService` (paling eksplisit, tidak bergantung `$casts`) |

## Perbaikan yang Dilakukan dalam Sesi Ini

### 1. `app/Console/Commands/TestEncryptionCommand.php`
**Masalah:** Memakai `App\Services\EncryptionGrpcService` yang tidak ada di codebase → `ClassNotFoundException` saat dijalankan.  
**Perbaikan:**
- Ganti dengan inject `EncryptionClientInterface` via parameter `handle()`
- Tambah health check sebelum round-trip
- Gunakan named arguments pada `decrypt()` agar konsisten dengan interface
- Kembalikan `self::SUCCESS`/`self::FAILURE` (bukan integer hardcoded)

### 2. `grpc_worker.php`
**Masalah:** Pakai nama env `ENCRYPTION_ENGINE_HOST` dan default `encryption-engine:50051` — berbeda dari `ENCRYPTION_SERVICE_HOST` / `encryption:50051` yang dipakai di seluruh konfigurasi Laravel lainnya.  
**Perbaikan:** Seragamkan ke `ENCRYPTION_SERVICE_HOST` dengan default `encryption:50051`.

### 3. `.env.example`
**Masalah:** Tidak ada satu pun placeholder untuk variabel encryption — developer baru yang clone repo tidak tahu variabel apa yang harus diisi.  
**Perbaikan:** Tambah blok 4 variabel dengan komentar penjelasan:
```
ENCRYPTION_SERVICE_HOST=encryption:50051
ENCRYPTION_SERVICE_API_KEY=
ENCRYPTION_SERVICE_TLS_ENABLED=true
ENCRYPTION_SERVICE_CA_CERT_PATH=/etc/ssl/certs/encryption-server.crt
```
